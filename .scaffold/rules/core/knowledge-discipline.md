# core.knowledge-discipline

## Applies When

- Creating or changing durable project knowledge
- Making a meaningful implementation change

## Guidance

- Treat project knowledge as durable intent and code as its implementation.
- Update durable knowledge when implementation reveals or changes important behavior, constraints, or reasoning.
- Classify evidence-backed code-style, build or compiler, formatting or linting, testing or quality-gate, and Git, pull-request, branching, or release practices as Project Rules. Leave a practice undefined when neither repository evidence nor maintainer input establishes it.
- Under the default Schema, Project Context may record the absence of a practice when material to orientation; it must not serve as the authoritative procedure or configuration record.
